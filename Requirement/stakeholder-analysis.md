Stakeholder Analysis — Online Movie Ticket Booking System

Stakeholder analysis identifies everyone who affects or is affected by the system, and how much each group should be engaged. Stakeholders are listed below with their interest level, influence, and key concerns.


1. Customers (Moviegoers)

Interest Level: High
Influence: Medium — their feedback drives feature priority

Key Concerns:
- Ease of use during browsing and checkout
- Fast, reliable payment processing
- Accurate, real-time seat availability
- Clear cancellation and refund process


2. Cinema Administrators

Interest Level: High
Influence: High — approves operational features

Key Concerns:
- Accurate and timely sales reporting
- Easy management of movies and showtimes
- Minimal manual work for day-to-day operations


3. Payment Gateway Provider

Interest Level: Medium
Influence: Medium — defines integration constraints

Key Concerns:
- Compliance with their API and security requirements
- Secure handling of transaction data
- Reliable error handling for failed payments


4. Project Sponsor / Instructor

Interest Level: High
Influence: High — approves scope and budget

Key Concerns:
- On-time delivery of milestones
- Adherence to the Agile process using Trello and GitHub
- Completeness and quality of documentation


5. Development Team

Interest Level: High
Influence: High — implements the solution

Key Concerns:
- Clear, unambiguous requirements
- Realistic sprint scope and workload
- Traceability between requirements, design, and tests


Requirement Gathering Techniques Used

- Stakeholder interviews (simulated) — discussions framed around representative customer and admin personas to surface needs.
- Brainstorming sessions — used during sprint planning to generate candidate user stories.
- Document analysis — benchmarking against existing cinema booking platforms, such as Fandango and BookMyShow.
- User story mapping — grouping stories into epics such as Account Management, Booking, Payment, and Admin, to visualize the release plan.
- Prototyping — low-fidelity wireframes for the seat map and checkout flow to validate usability assumptions early.


Stakeholder Engagement Plan

Customers are engaged on an ongoing basis through usability feedback and simulated UAT sessions.
Cinema Administrators are engaged weekly through sprint review demos.
Payment Gateway Provider is engaged as needed, through API documentation review.
Project Sponsor / Instructor is engaged at the end of each sprint, through sprint review and report submission.
Development Team is engaged daily, through Trello board updates and sprint planning sessions.
